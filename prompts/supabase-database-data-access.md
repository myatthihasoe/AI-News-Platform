# Biasly Supabase database and data access

## Goal

Implement the initial Supabase/Postgres persistence layer and a typed, server-only data access layer for Biasly News. Supabase becomes the source of truth for sources, scraped articles, AI analyses, pipeline logs, Oxylabs schedules, and Oxylabs schedule runs. Wire the existing home feed and news detail route to the new query layer now, reshape the components from the preview's clustered multi-source model to the persisted one-article-per-source model, and render deliberate empty/fallback states until scraping and analysis produce rows.

## Decisions and assumptions

- Use Clerk for application authentication; do not add or use Supabase Auth.
- Access all Biasly tables through server-only code using `SUPABASE_SERVICE_ROLE_KEY`. Never construct the privileged client in a Client Component or expose the key.
- Keep the home feed publicly browseable later through Server Components; no anonymous browser-to-Supabase table access is required for this task.
- Put the application tables in `public` so `supabase-js` can use the Data API, but explicitly grant table/sequence access only to `service_role` and revoke access from `anon` and `authenticated`.
- Enable RLS on every public table. Do not add broad public policies. The service role is the only application database role used by this layer and bypasses RLS.
- Add `slug` and the minimal article presentation metadata (`author`, `category`, `region`, `image_alt`, and `read_time_minutes`) because the existing application routes and cards require them. Do not add speculative personalization or user tables.
- Store Oxylabs schedule, run, and job identifiers as `text`, never as JavaScript numbers, because they may exceed `Number.MAX_SAFE_INTEGER`.
- Do not add pgvector or `article_analyses.embedding`; that is a later phase after analysis works.
- Seed only the five sources explicitly requested by the user, using their verified official homepage listing URLs. Keep seed data in `supabase/seed.sql`, not `supabase/schema.sql` or the migration.
- Wire `app/page.tsx` and `app/news/[slug]/page.tsx` to server-only Supabase queries. Do not retain preview articles as runtime fallbacks; an empty database must produce intentional empty/not-found UI.
- The persisted model is one article per source. Remove clustered-story assumptions such as aggregate source counts, `topSources`, and hand-authored related stories from page/component props. A single article's source name replaces the cluster count. Related articles remain absent until the later pgvector phase.
- Pin package versions exactly and commit the lockfile. At planning time the current compatible releases are `@supabase/supabase-js@2.112.0` and `supabase@2.110.0`; verify them once more immediately before installation.
- The local environment has Node `v24.15.0`, which satisfies the SDK's current Node requirement.

## Database schema requirements

Create the same idempotent canonical schema in `supabase/schema.sql` and the initial generated migration. Use lowercase snake_case identifiers, `bigint generated always as identity` primary keys, `text` for strings, `timestamptz` for timestamps, JSONB only for genuinely structured metadata, and explicit `check` constraints.

### `sources`

- `id` identity primary key
- unique, non-empty `name`
- unique, non-empty `listing_url`
- `parser_strategy jsonb not null default '{}'::jsonb`
- `is_active boolean not null default true`
- nullable `logo_url`
- `created_at` and `updated_at` with `now()` defaults

### `articles`

- `id` identity primary key
- `source_id` required foreign key to `sources`, with a deliberate non-destructive delete action
- unique, non-empty `original_url`
- unique, non-empty `canonical_url`
- unique, non-empty `slug`
- non-empty `title`
- required, non-empty `image_url`; nullable `image_alt`
- nullable `author`, `category`, and `region`
- required `published_at`
- required, non-empty `raw_text`
- nullable positive `read_time_minutes`
- `scraped_at` defaulting to `now()`
- nullable `analyzed_at`, set only after valid analysis storage
- `created_at` and `updated_at`

Articles are append-only in scraping code. Enforce URL and slug uniqueness in Postgres; data-access helpers must not update or delete existing articles as part of dedupe.

### `article_analyses`

- `id` identity primary key
- unique `article_id` foreign key to `articles`, allowing exactly one current analysis row per article
- required `summary`
- `sentiment_score` constrained to `-1..1`
- `sentiment_label` constrained to `positive | neutral | negative`
- `left_percentage`, `center_percentage`, and `right_percentage` as integers constrained to `0..100`, plus a table constraint requiring their sum to equal `100`
- `bias_score` as a stored generated column derived from `(right_percentage - left_percentage) / 100`, constrained to `-1..1` by construction
- `bias_label` constrained to `left | center | right | mixed | unclear`
- `confidence` constrained to `0..1`
- required `framing_notes`
- `loaded_terms text[] not null default '{}'`
- required `disclaimer` and non-empty `model`
- `created_at` and `updated_at`
- no embedding column in this migration

### `logs`

- identity primary key
- constrained `level` (`debug | info | warn | error`)
- non-empty `event_type` and `message`
- nullable foreign keys to `sources` and `articles` using a safe delete action
- `metadata jsonb not null default '{}'::jsonb`
- `created_at`

### `oxylabs_schedules`

- identity primary key
- unique `source_id` foreign key to `sources`
- unique, non-empty `oxylabs_schedule_id text`
- constrained local state (`active | inactive | error`)
- nullable `last_synced_at` and `last_error`
- `created_at` and `updated_at`

### `oxylabs_schedule_runs`

- identity primary key
- required foreign key to the local `oxylabs_schedules` row
- required `oxylabs_run_id text` and `oxylabs_job_id text`
- constrained Oxylabs result status (`pending | done | faulted`)
- constrained local processing status (`pending | processing | processed | failed`)
- `summary jsonb not null default '{}'::jsonb`
- nullable `processed_at` and `error_message`
- `created_at` and `updated_at`
- uniqueness that prevents the same schedule/job result from being recorded twice

### Indexes and privileges

- Index every foreign key that is not already covered by a unique constraint.
- Add only query-driven indexes: active sources, articles by source/published date, article feed ordering, pending article analysis, recent logs, and schedule-run status/recency.
- Prefer partial indexes for `sources.is_active`, `articles.analyzed_at is null`, and pending/unprocessed schedule runs where appropriate.
- Enable RLS on all six tables.
- Revoke all privileges on these tables and their sequences from `anon` and `authenticated`.
- Grant the minimal required table and sequence privileges explicitly to `service_role`, accounting for Supabase's new explicit-grant defaults.
- Do not grant browser roles access and do not create permissive `using (true)` policies.

## Data-access requirements

All query modules must contain `import "server-only"`, select only required columns, return narrow typed results, and throw contextual errors when Supabase returns an error.

### Sources

- List active sources in a deterministic order.
- Optionally fetch a source by ID when needed by future pipeline code.
- Do not hardcode source URLs in the query module; source values live only in the requested seed file and database rows.

### Articles

- Insert one validated article without upserting or overwriting existing rows.
- Find already stored original/canonical URLs for dedupe. Normalize and deduplicate the input and split every `.in()` request into chunks of at most 15 URLs.
- List analyzed articles for a public feed with an explicit bounded limit and stable ordering.
- Fetch one article and its source/analysis by slug.
- Find pending-analysis articles based on the actual absence of an `article_analyses` row, not only `articles.analyzed_at is null`.
- Never use `.eq('foreignTable.column', value)` on a joined table. Fetch the nested relation and apply joined-relation conditions in JavaScript where needed.

### Analyses

- Insert exactly one valid analysis row for an article.
- Provide a focused helper to mark `articles.analyzed_at` only after the valid analysis insert succeeds.
- Do not add embeddings or AI/model calls in this task.

### Logs

- Insert structured logs.
- List recent logs with a bounded limit and optional safe filters.

### Oxylabs schedules and runs

- List schedules and schedule runs with bounded, stable ordering.
- Insert/update schedule metadata without converting external IDs to numbers.
- Insert a run idempotently by schedule/job identity and update its processing state with narrow allowed inputs.
- Do not call Oxylabs or implement scheduler routes in this task.

## Security requirements

- No service-role key, database row, or privileged query module may enter a client bundle.
- No direct Supabase calls from Client Components.
- No use of Supabase Auth; Clerk remains the only user authentication system.
- RLS enabled on every public table, plus explicit least-privilege grants.
- No public read/write policies in this task.
- Validate or constrain all enum-like values, percentages, confidence/scores, non-empty required strings, and foreign-key relationships.
- Do not add destructive cascade behavior unless dependent rows have no independent meaning; sources must not be deletable when articles/schedules still reference them.
- Do not expose raw internal records through an API or modify any auth middleware/routes.

## Acceptance criteria

- The canonical SQL and initial migration create all six required tables with matching constraints, foreign keys, indexes, RLS, and explicit grants.
- `article_analyses` percentages cannot fail to sum to 100, and `bias_score` is database-derived.
- Oxylabs identifiers remain exact strings end to end.
- `lib/supabase/types.ts` matches the SQL schema and is accepted by `createClient<Database>`.
- The Supabase client can only be imported server-side and uses the service role without session persistence.
- Query helpers cover active sources, article insertion/dedupe/feed/detail/pending analysis, analysis persistence, logs, schedules, and runs.
- URL existence checks never pass more than 15 values to one `.in()` filter.
- Joined-table filtering follows the repository's JavaScript-filter rule.
- Existing visual styling and Clerk auth remain intact while the homepage and detail page become database-backed.
- A fresh database with only seed sources renders a deliberate empty home state; detail slugs return the normal not-found page.
- Feed/detail components no longer require mock-only source counts, `topSources`, or related story arrays.
- The detail page renders all stored analysis fields and links back to the article's actual source URL.
- No pgvector, scraping, scheduler API, AI analysis, article mocks, or unrelated refactor is introduced. The only seed URLs are the five explicitly requested homepage entry pages in `supabase/seed.sql`.
